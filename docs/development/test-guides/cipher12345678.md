# 本地开发登录口令指南（初始口令文件）

> 本文档介绍本地开发环境如何拿到管理员初始口令并登录 SecretPad。
>
> **历史说明**：本文件名沿用自"固定口令 `admin / 12345678`"时期。该固定口令已随安全整改
> P0-1（见 `docs/secretpad_auth.md` §3.1）**整体删除**：源码里不再存在任何口令常量，
> `AuthConstants.getRandomPassword()` / `generateRandomPassword()` 恢复为 `SecureRandom` 生成的
> 16 位四类字符口令，启动日志不再打印口令，已存在账号的口令在重启时不再被覆盖。

## 1. 规则

| 情形 | 行为 |
|---|---|
| 首次启动，未设置 `SECRETPAD_PASSWORD` | 生成随机口令，**只**写入 `secretpad.auth.initial-password-file`（默认 `./config/initial-admin-password`，0600） |
| 首次启动，设置了 `SECRETPAD_PASSWORD` | 用该口令建户，不写文件 |
| 账号已存在 | 一律不动（不论环境变量给了什么），日志 `user admin already exists, password left untouched` |

## 2. 快速开始

```bash
# 启动后端（IDE 或 mvn），在 secretpad-web 目录下
cat config/initial-admin-password        # 取初始口令
# 浏览器打开 http://localhost:8000，输入 admin / <初始口令>
# 登录后在右上角用户菜单修改密码，然后：
rm config/initial-admin-password
```

想固定一个开发口令，用环境变量而不是改代码：

```bash
export SECRETPAD_USER_NAME=admin
export SECRETPAD_PASSWORD='Dev-Passw0rd!'   # 只在首次建户时生效
```

## 3. 重置

数据库里已有 `admin` 时重启不会重置口令。要重新初始化：

```bash
sqlite3 db/secretpad.sqlite "delete from user_accounts where name='admin';"
# 重启后会重新生成初始口令文件
```

## 4. 为什么不再提供固定口令

- 固定口令等于把管理员口令写进镜像，任何能拉到镜像的人都能登录；
- 启动覆盖口令使用户改过的口令在重启后失效，等于"口令永远是默认值"；
- 日志打印口令使任何能读日志的人（日志平台、运维、备份）都持有管理员口令。

这三条都由用例守着：`AuthConstantsTest`（无固定常量、随机且四类齐全）、`DbDataInitTest`（已存在不覆盖、
文件里的口令就是能登录的口令、文件 0600）、`StartupBannerTest`（横幅不含口令）。
