# SecretPad 前端架构重塑方案（综合最优版）

> 版本：2.0 | 综合 Kimi 方案（工程实践 + 量化诊断 + 灰度迁移）与 Qoder 方案（类型安全 + 现代路由 + 领域层）的最优内容。
> 目标：从「Umi 4 + Valtio 单体应用」演进为「Vite + FSD + TanStack + 设计系统」的模块化工业级前端。

---

## 1. 现有架构诊断

### 1.1 工程概况（量化）

| 维度 | 现状 | 量化数据 |
|------|------|----------|
| 框架 | Umi 4（约定式路由、运行时编译） | 框架锁定深，配置黑盒 |
| 状态管理 | 自制 Valtio Model 类 + WeakMap 全局单例 | 生命周期不可控、单测困难 |
| 服务端状态 | 无缓存，每个页面 `useEffect` 直接请求 | 重复请求、无失效策略 |
| 网络层 | `umi-request` + 自动生成的 Controller 文件 | 无运行时校验、错误处理分散 |
| 样式 | Less 文件，全局/模块混合 | 主题切换不统一、Token 未收敛 |
| 模块组织 | 49 个 `modules/` 按技术/页面命名 | 跨域引用、公共 API 难收敛 |
| 测试 | Jest 覆盖率为主，MSW/E2E 未体系化 | 集成测试薄弱 |
| 构建 | Umi 内置 Webpack，MFSU 已关闭 | HMR > 1s、冷启动 > 15s |
| 安全 | `User-Token` 存 `localStorage` | XSS 风险、刷新策略缺失 |
| 权限 | 10 个路由 wrapper（center-auth、p2p-auth...） | 权限判断分散 |

### 1.2 核心痛点

1. **框架与运行时耦合**：`umi-request`、`history`、路由守卫、API 生成全部依赖 Umi 运行时。多端输出（微前端、Electron）迁移成本极高。

2. **状态管理失控**：`valtio-helper.ts` 通过 WeakMap 把每个 Model 类变成全局单例。模块卸载不释放、测试间污染、不可 SSR/微前端隔离。

3. **服务端状态无管理**：列表/详情页各自 `useEffect` 拉数据，缺少分页缓存、乐观更新、去重、重试。用户体验是"每次切换都 Loading"。

4. **业务模块未真正自治**：`modules/` 下各模块之间大量引用 `services/secretpad/*` 与 `util/valtio-helper`，形成蜘蛛网依赖。

5. **API 与类型不可靠**：OneAPI 生成 Controller 后没有运行时校验，后端字段变更时前端无法感知。

6. **主题与品牌扩展困难**：大量组件硬编码颜色/字号，暗色模式、高密度模式、品牌定制难以落地。

7. **权限模型混乱**：路由守卫写了 10 个 wrapper，权限判断分散在路由配置和组件内部。

8. **性能与可观测性缺失**：没有 Web Vitals 上报、没有 Sentry、没有路由级错误边界。

---

## 2. 重塑目标

| 目标 | 验收标准 |
|------|----------|
| 解耦框架 | 业务代码不依赖任何框架 API，路由/构建/请求可替换 |
| 模块自治 | 任何 Feature 可独立开发、测试、发布（Module Federation 就绪） |
| 类型安全 | OpenAPI 生成类型 + Zod 运行时校验，接口错误率降低 60% |
| 状态可预测 | 服务端状态用 TanStack Query，客户端状态用 Zustand，不可变快照 |
| 体验提升 | 路由级代码分割、骨架屏、乐观更新、TTI < 3s |
| 工程领先 | Vite HMR < 200ms、ESLint flat config、CI 全链路校验 |
| 安全合规 | Token httpOnly、RBAC 统一、CSP 部署 |
| 可观测 | Sentry + Web Vitals + 关键埋点，错误 5 分钟内可定位 |

## 3. 新架构设计

### 3.1 技术栈选型

| 层级 | 旧方案 | 新方案 | 理由 |
|------|--------|--------|------|
| 构建 | Umi 4 (Webpack) | **Vite 5 + React 18** | 原生 ESM、极速 HMR、产物透明 |
| 路由 | Umi 约定式 | **TanStack Router** | 端到端类型安全、loader 模式、searchParams 序列化 |
| 状态（服务端） | useEffect 直调 | **TanStack Query v5** | 缓存、去重、重试、乐观更新、DevTools |
| 状态（客户端） | Valtio 单例 | **Zustand + Immer** | 轻量、可测试、可隔离、中间件生态 |
| 表单 | antd Form | **React Hook Form + Zod** | 性能、类型校验、可组合 |
| 网络 | umi-request | **openapi-fetch + Axios 兜底** | 零运行时类型安全 + 拦截器统一 |
| 运行时校验 | 无 | **Zod** | 开发环境 schema 验证，生产上报 |
| 样式 | Less | **Tailwind CSS + CSS Variables** | Token 化、主题切换、树摇友好 |
| 组件库 | Ant Design 5 | **Ant Design 5 + 自研 Design System** | 保留资产，收敛封装层 |
| 表格 | antd Table | **TanStack Table + antd 样式** | 虚拟滚动、筛选解耦 |
| DAG | @antv/x6 + @secretflow/dag | **保留 X6，独立 packages/dag-next** | 继承能力，ESM 化 |
| 测试 | Jest | **Vitest + RTL + MSW + Playwright** | 与 Vite 同构、统一生态 |
| Lint/Format | ESLint 8 + Prettier | **ESLint 9 flat + Biome** | 更快、flat config |
| 图表 | AntV/G2 + S2 | **保留并封装** | 已有图表能力不丢弃 |

### 3.2 分层架构（FSD + Clean Architecture 融合）

```
┌──────────────────────────────────────────────────────────┐
│                   apps/secretpad                           │
│              (Vite entry, React 18)                        │
├──────────────────────────────────────────────────────────┤
│  pages/          路由薄壳：组合 widgets + features         │
├──────────────────────────────────────────────────────────┤
│  widgets/        可跨页面复用的复合 UI 块                   │
│                  (header, sidebar, filter-bar, table)      │
├──────────────────────────────────────────────────────────┤
│  features/       业务领域模块（自治）                       │
│  ├─ api/         queries + mutations (TanStack Query)      │
│  ├─ model/       zustand slice / types                     │
│  ├─ lib/         domain logic（纯函数）                    │
│  ├─ ui/          components + hooks                        │
│  └─ index.ts     public API（唯一出口）                    │
├──────────────────────────────────────────────────────────┤
│  entities/       跨领域实体类型与简单规则                   │
│                  (User, Node, Project, DataTable)          │
├──────────────────────────────────────────────────────────┤
│  shared/         共享基础设施                              │
│  ├─ api/         client + interceptors + generated         │
│  ├─ ui/          design system 原子组件                    │
│  ├─ hooks/       通用 hooks                               │
│  ├─ lib/         utils, sanitize, logger, result           │
│  ├─ theme/       tokens + theme-provider                   │
│  ├─ i18n/        国际化配置                               │
│  └─ config/      环境变量、平台常量                        │
└──────────────────────────────────────────────────────────┘
```

**依赖规则（严格单向）：**
```
app → pages → widgets → features → entities → shared
```
- 同层不可互相引用
- 禁止反向依赖
- Feature 之间禁止直接引用（通过 shared 事件或 URL 参数通信）
- 任何模块只通过 `index.ts` 暴露 public API

### 3.3 关键领域设计

#### 3.3.1 认证与授权（Auth）

```
features/auth/
  ├─ api/        loginQuery, refreshTokenMutation
  ├─ lib/        rbac.ts（权限计算）, platform-type.ts（CENTER/EDGE/P2P）
  ├─ model/      auth-store.ts（Zustand，token 仅存内存）
  └─ ui/         LoginPage, RequiredAuth, RequiredPermission, usePermission()
```

- 路由守卫统一为 `RequiredAuth` + `RequiredPermission` 组合组件，**替代 10 个 wrapper**
- 平台类型由后端登录接口返回，统一写入 `authStore`
- Token 由后端写入 httpOnly cookie，前端不接触敏感存储

#### 3.3.2 服务端状态（TanStack Query）

```typescript
// features/project/api/project-queries.ts
import { queryOptions } from '@tanstack/react-query';
import { apiClient } from '@secretpad/api-client';

export const projectQueries = {
  all: () => ['projects'] as const,
  list: (params: ListProjectParams) =>
    queryOptions({
      queryKey: [...projectQueries.all(), 'list', params],
      queryFn: () => apiClient.GET('/api/v1alpha1/project/list', { params }),
    }),
  detail: (id: string) =>
    queryOptions({
      queryKey: [...projectQueries.all(), 'detail', id],
      queryFn: () => apiClient.GET('/api/v1alpha1/project/get', {
        params: { query: { projectId: id } },
      }),
    }),
};

// 页面使用
const { data, isLoading } = useQuery(projectQueries.list(params));
```

#### 3.3.3 客户端状态（Zustand）

```typescript
// features/dag/model/dag-ui-store.ts
import { create } from 'zustand';
import { devtools } from 'zustand/middleware';

interface DagUIState {
  selectedNodeId: string | null;
  zoom: number;
  setSelectedNodeId: (id: string | null) => void;
  setZoom: (zoom: number) => void;
}

export const useDagUIStore = create<DagUIState>()(
  devtools((set) => ({
    selectedNodeId: null,
    zoom: 1,
    setSelectedNodeId: (id) => set({ selectedNodeId: id }),
    setZoom: (zoom) => set({ zoom }),
  }))
);
```

仅放置 UI 状态（侧边栏展开、当前 Tab、画布缩放），不放置服务端数据。

#### 3.3.4 网络层与校验

```
shared/api/
  ├─ client.ts          openapi-fetch 实例 + Axios 兜底
  ├─ interceptors/
  │   ├── auth.ts       401 → refresh → 重放
  │   ├── trace.ts      请求追踪 ID
  │   └── error.ts      错误分类 → Toast/重定向
  ├─ generated/         OpenAPI 自动生成的类型和请求函数
  └─ types.ts           通用响应类型

shared/lib/
  └─ zod-schemas/       手动维护的运行时校验（开发环境）
```

所有 API 响应经过 `zod.parse()` 验证：开发环境报错，生产环境上报 Sentry。

#### 3.3.5 设计系统（Design System）

```
packages/design-system/
  ├─ tokens/            CSS Variables / Design Tokens (JSON)
  ├─ theme/             亮色/暗色/品牌色主题
  ├─ components/        封装后的 Button、Table、Form、Modal
  ├─ hooks/             useTheme, useMediaQuery
  └─ stories/           Storybook 组件文档
```

- 所有颜色、间距、字体全部使用 Token
- 主题切换通过 `data-theme` 属性 + CSS Variables，无闪屏
- Ant Design 5 通过 ConfigProvider 消费 Token，保持兼容

#### 3.3.6 路由设计（TanStack Router）

```typescript
// apps/secretpad/src/app/routes.tsx
import { createRootRoute, createRoute, createRouter } from '@tanstack/react-router';

const rootRoute = createRootRoute({ component: AppLayout });

const dashboardRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/',
  component: () => import('../pages/dashboard'),
});

const pipelineRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/pipeline/$projectId',
  component: () => import('../pages/dag'),
  loader: ({ params }) => prefetchProject(params.projectId), // 数据预加载
});

// searchParams 类型安全
const projectsRoute = createRoute({
  getParentRoute: () => rootRoute,
  path: '/projects',
  validateSearch: (search) => ({
    page: Number(search.page) || 1,
    keyword: String(search.keyword || ''),
  }),
});
```

## 5. 迁移路线图

| 阶段 | 时间 | 目标 | 产出 |
|------|------|------|------|
| **P0：基础搭建** | 2 周 | Vite 工程、路由、网络层、鉴权、设计 Token | 可运行空壳项目 |
| **P1：核心领域迁移** | 4 周 | Dashboard、Login、Project、Node、Data 迁移到 FSD | 旧页面流量 80% 切换 |
| **P2：复杂模块迁移** | 4 周 | DAG 画布、模型管理、隐私计算、定时任务 | 功能等价 |
| **P3：工程补齐** | 2 周 | E2E、性能监控、可访问性审计、文档 | 上线就绪 |

### 5.1 低风险迁移策略（灰度双轨）

1. **双应用并行**：旧 Umi 应用与新 Vite 应用同时构建，通过 Nginx 按路径灰度
2. **API 层复用**：先把 `services/secretpad` 迁移到 `packages/api-client`，旧新同时引用
3. **组件渐进替换**：从 Header、Footer、Table 等低复杂度组件开始
4. **特性开关**：使用 `window.__NEW_ARCH_ENABLED__` 或 LaunchDarkly 控制新页面开关
5. **回滚保障**：灰度路由 + 功能开关 + 旧版本保留 2 个迭代

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| DAG 画布依赖 X6 与大量自定义 Less | 高 | 作为独立 `packages/dag-next` 保留，逐步 ESM 化 |
| 后端 API 无 OpenAPI 完整描述 | 中 | 推动后端补齐 Swagger；过渡阶段手写 Zod schema |
| Ant Design 5 与 Tailwind 冲突 | 中 | ConfigProvider Token 映射 + preflight 关闭 |
| 团队成员熟悉 Umi 但不熟悉 Vite | 中 | 脚手架 + 文档 + 示例 Feature + Code Review |
| 上线回滚 | 中 | 灰度路由 + 功能开关 + 旧版本保留 |
| 后端 API 变更 | 低 | openapi-typescript 自动生成 + CI 检测 breaking change |

## 7. 与现有系统对比

| 维度 | 现有 (frontend-src) | 新方案 |
|------|---------------------|--------|
| 构建速度 | Webpack ~15s 冷启动 | Vite < 1s |
| 类型安全 | TS 4.9 非严格 | TS 5 strict + 端到端类型 + Zod 运行时 |
| 状态管理 | 自定义 Valtio Model（不可销毁） | TanStack Query + Zustand（可隔离） |
| 模块化 | 平铺 49 modules，蜘蛛网依赖 | FSD 6 层分层，严格单向依赖 |
| 样式 | Less 变量，硬编码颜色 | Design Token + Tailwind + CSS Variables |
| 测试 | Jest 少量 | Vitest + RTL + MSW + Playwright 全链路 |
| API | umi-request + 手动类型 | openapi-fetch 零运行时 + Zod 校验 |
| 路由 | Umi 约定式 + 10 个 wrapper | TanStack Router 类型安全 + 2 个守卫 |
| 主题 | 手动 Less 覆盖 | CSS Variables 运行时切换，无闪屏 |
| 可观测性 | 无 | Sentry + Web Vitals + 埋点 |
| 安全 | Token 存 localStorage | httpOnly cookie + CSP + RBAC |

## 8. 结论

新架构通过 **FSD 分层 + Vite 5 + TanStack Router/Query + Zustand + Design System + Zod** 解决现有框架锁定、状态混乱、模块耦合、类型不可靠、安全缺失的问题。

核心优势：
- 取 Kimi 方案之长：量化诊断、widgets 层、entities 层、灰度双轨迁移、DAG 独立包、平台类型处理
- 取 Qoder 方案之长：TanStack Router 类型安全、openapi-fetch 零运行时、Biome 格式化、领域端口概念、i18n、可扩展性设计

迁移采用双轨灰度策略，确保业务功能不中断的前提下完成技术升级。
